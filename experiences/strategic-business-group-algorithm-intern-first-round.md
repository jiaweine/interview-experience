## 一、面试整体情况

这次滴滴一面主要围绕 Agent 相关项目、记忆与反思机制，以及金融文档处理和投研检索系统展开。

面试官的提问不仅涉及模块定义，还深入到评测规模、性能开销、实际失败案例、问题原因和改进思路。后半段转向金融文档处理的输入输出、数据边界以及检索规划。

**这场一面通过了，后续进入二面。** 下面按话题记录提问内容。

## 二、Agent 记忆与反思机制

- Memory Patch 和 Reflection Gate 分别是什么？在系统中起什么作用？
- 为什么要设置反思门控，而不是每次执行都触发反思？
- 这套机制最终在什么规模的数据上评测？准确率和提升幅度如何？
- 完整评测的耗时如何？有没有某个环节特别耗时？
- 实际运行和评测过程中遇到了哪些困难？
- 哪个问题最难解决，为什么？

其中，面试官对评测数字、额外耗时以及困难案例有连续追问。

## 三、伪成功样本与错误记忆

这部分讨论得比较深入，主要包括：

- Agent 表面上完成了任务，但生成了错误反思，为什么会出现这种伪成功样本？
- 如果错误反思进入长期记忆，后续任务会受到什么影响？
- 反思门控是否只关注任务最终状态？能否检查反思内容本身是否真实？
- 怎样防止模型编造的反思经验反复污染记忆？
- 除了推理时验证，能否在训练阶段通过 SFT 或强化学习减少这类错误？

这几个问题不只是考察概念，更关注真实系统中不容易被最终结果指标暴露的问题。

## 四、Skill 自进化与 Harness

- Skill Generic 自进化框架具体是什么？
- Skill 能否根据历史经验迭代？如何判断更新是否有效？
- Harness 与 Agent 有什么区别？各自承担什么职责？

## 五、金融文档处理与投研检索

后半段转向金融相关项目，面试官主要问到：

- 系统最终输出的是什么？
- 处理单个 PDF、网页还是批量文档？是否会主动向外扩展数据源？
- 用户输入问题后，系统是怎样检索本地文档的？
- 检索规划具体指什么？与普通的向量相似度召回有什么区别？
- 投研场景下，用户输入一个问题，最终会得到怎样的输出？
- 与直接在通用大模型里上传一批文档再提问相比，这套系统有什么区别？
- 对复杂投研问题，如何判断本地证据是否足够，以及何时需要补充检索？

## 六、面试感受与结果

这次面试的技术讨论比较充分。面试官会顺着项目继续追问，不仅关注做了什么，还关心如何评估效果、性能代价有多大、实际遇到什么问题，以及针对问题还能怎么改进。

其中，**伪成功样本和错误反思污染记忆**这一部分给我留下了比较深的印象，相关问题连续问了多轮。

整体交流下来，我对问到的问题基本都进行了回答。**最后一面通过，进入后续流程。** 这里仅记录一面结果，不代表最终获得实习录用。
