# 网易易盾人工智能算法实习生面试经历：GRPO 问到底，Deepfake 方案讲完，面完却很快被拒

**公司：** 网易易盾  
**面试岗位：** 人工智能算法实习生  
**面试方式：** 视频面试  
**面试日期：** 2026-09-11  
**面试体验：** 技术提问深入，但结果来得过于突然，整体感受很差  
**说明：** 以下根据当次交流和个人回忆整理，具体面试过程与主观感受分开叙述。

## 一、项目介绍：从 Agent 行为链路一路追问到 GRPO

一开始，我介绍了自己做的 EvoSkill-Harness。它是面向内部文本处理和语料生产的 Skill-Centric Agent 后训练框架，目标是解决固定流水线执行路径僵化、中间失败必须全链路重跑、线上失败经验难以沉淀等问题。

方案上，我们把能力封装成带契约的 Skill，用 Graph of Skills 管理前置依赖、路由条件和动态分支；通过 Trace Verifier 对执行过程做校验，将失败区分为策略缺陷和能力缺口。线上快环负责局部修复和策略补丁，离线慢环采用 LoRA-SFT 和 GRPO 优化路由与修复选择。评测中 Skill 路由 Top1 达到 93.5%，多步任务完成率相比固定流水线提升 6.7 个百分点。我主要负责技能图生命周期管理和 Trace Verifier。

面试官先确认，这是否主要是在微调 Agent 的行为链路，以最终任务达成为目标。我解释了区别于只优化最终文本输出，我们更关注规划、技能调用、过程校验和错误回退。

之后围绕项目持续深入追问：

- **Graph of Skills 到底是什么。** 我解释了 Skill 节点、依赖和跳转边、动态分支，以及初始化、更新、失效淘汰和按归因结果调整路由条件的生命周期。
- **Trace Verifier 如何评分。** 我分别介绍了格式、证据、风格、语义四个维度。格式核对 Skill 输出的 schema，证据检查结论是否得到工具结果支持，风格检查输出范式，语义判断是否完成当前子任务，并用各维度得分辅助定位失败原因。
- **策略缺陷与能力缺口怎么区分。** 前者是选错 Skill 或路径，优先调整路由策略；后者是技能选对了，但执行输出不达标，需要收集训练样本，进一步优化模型能力。

到这里都还是围绕项目展开的正常技术交流，我也逐项作了解释。

## 二、GRPO：奖励公式、全零组和异常梯度都问了

随后面试官重点追问 GRPO，先问奖励函数为什么这样设计，再要求给出明确的数学形式、奖惩数值和权重。

我给出的设计是将最终任务奖励、过程校验奖励和路由合规奖励加权组合：

```text
R = 0.6 * R_final + 0.3 * R_trace + 0.1 * R_route
```

最终任务成功和失败分别给正负奖励；过程奖励来自 Verifier 的连续评分；路由奖励约束 Skill 图中的合法跳转。这样设计是为了避免模型只顾最终答案，而忽略中间执行路径的可靠性。

面试官接着问，如果 GRPO 同一个采样组的奖励全为 0，组内没有有效优势信号，应该怎么办。我回答了低方差组识别、跳过无效更新、记录对应样本，并通过 LoRA-SFT 预热改善早期有效采样比例。

之后又问到个别样本梯度特别大时如何处理。我从策略比率裁剪、梯度范数裁剪、奖励范围约束和异常样本日志分析几个方面回答。

**这部分并不是只停留在概念层面。** 从奖励目标到具体数值，再到低方差组和异常梯度，面试官反复往下追问，我也针对每个问题给出了自己的处理方法。当然，方案中的阈值和权重是否最优，还需要实验验证，但至少不是没有回答，更不是只会背 GRPO 名词。

## 三、开放题：十分钟设计一套 Deepfake 人脸检测方案

后面面试官又出了一个与前面 Agent 后训练项目不同的开放性建模题：正样本是 Deepfake 伪造人脸，负样本是真实人脸，正样本极少。要求自行考虑小模型 Backbone 选型、结构改造、训练策略、损失函数和效果评估，还希望借助大模型辅助建模，但最终推理必须依靠小模型。

给了大约 10 分钟思考时间。

我给出的方案不只是选一个分类模型，而是从数据到训练、评测做了完整设计：

1. **数据与划分。** 检测并裁剪人脸，保留融合边界信息；按人物身份和原始视频源划分数据，避免同源泄露；训练时处理类别不平衡，测试时保留真实分布，并加入未见过的伪造手法检验泛化。
2. **Backbone 与结构。** 以轻量化 EfficientNet-B0 为主干，增加高频残差分支，尝试捕捉换脸融合边缘、局部纹理和细粒度伪造痕迹，再通过消融实验判断新增分支是否真正有效。
3. **训练与损失。** 先训练新增分支及分类头，再小学习率全局微调；以 Focal Loss 处理大量简单负样本，同时讨论正样本间隔约束及防止特征分支失效的辅助约束。
4. **指标与验证。** 不以整体 Accuracy 掩盖类别不平衡，重点关注 PR-AUC、固定低误报率下的召回、精确率和推理延迟。阈值只在验证集选择，最终用测试集检验泛化。

面试官继续追问 EfficientNet-B0 之外还有哪些系列，我回答了 B0 到 B7、EfficientNet-Lite，以及 EfficientNet-V2 的不同规模与适用场景。

紧接着，又追问我提到的负载均衡损失具体该怎么设计。我解释，这里并不是 MoE 的专家负载均衡，而是设想对主干与高频残差分支的响应贡献施加轻量辅助约束，避免新增分支长期被模型忽略；也说明这属于需要通过消融实验确认收益的设计，而不是可以直接保证有效的成熟结论。

**开放题本来就是让候选人拿出建模思路。我把数据、模型、损失、训练、指标和后续追问都回答了，至少是在认真完成对方给出的题目。** 具体方案可以讨论优劣，辅助损失也可以被质疑，但这些恰好应该成为进一步技术讨论的内容。

## 四、面试结束后很快被拒：到底在考察什么？

真正让我感到不舒服的是，**面试结束后很快就收到了不通过的结果。**

我并不是认为回答了所有问题就一定应该通过，也不认为自己给出的每个方案都没有缺陷。比如 Deepfake 任务里额外引入分支约束是否有收益，需要真实实验支撑；GRPO 的奖励权重和训练异常处理，也完全有继续细问的空间。

但这次面试官要求的内容确实不少：不仅要我讲清楚项目架构、技能图和过程校验，还进一步问到 GRPO 奖励数学形式、具体奖惩、全零奖励组、异常梯度；随后又让我在短时间内从头设计一套类别极不平衡的 Deepfake 检测方案，连 Backbone 衍生版本、辅助损失都继续追问。

**我认真把思路展开，也尽可能逐项回答。结果面试刚结束不久就被拒，实在让人有很强的落差感。**

一个候选人是否合适，当然不只取决于能不能答出问题。可经历了这样一轮较为深入的技术讨论，最终如此迅速地结束，作为候选人，我确实很难不怀疑：这些问题到底是在认真评估岗位匹配度，还是更希望听到一套现成的设计思路？

尤其是 Deepfake 开放题，实际上已经接近一轮完整的小模型建模方案讨论。**我甚至产生了一种被叫来输出技术方案、输出完就被筛掉的感觉。** 这种感觉很不舒服，甚至有点像被戏耍了一顿。

这里也必须说清楚：**这是我当次面试的主观感受，并不能据此认定面试官或团队真的在套方案。** 但这种怀疑之所以会出现，正是因为面试中投入了大量具体的设计讨论，结果却来得非常突然。

## 五、个人复盘：能接受被拒，但这次体验仍然让我失望

客观地说，这场面试的技术追问并不浅。GRPO 奖励和训练稳定性问得细，Deepfake 开放题也覆盖了从结构到训练、损失、评估的全流程。相比只问几个名词就草率结束的面试，这次至少有实质性的技术讨论。

我也知道自己还有改进空间。特别是面对自己临时提出的模块与辅助损失，最好进一步明确变量定义、损失函数是否必要、可能的副作用，以及如何通过消融排除收益只是来自参数量增加。能够描述一个方案，不代表方案经过了充分验证。

**但我不认可的一点是，候选人认真完成了大量开放式技术问答，却只能面对一个来得很快的淘汰结果，几乎无法从结果本身知道到底差在哪里。**

如果核心要求是某类视觉算法经验，或者必须有特定业务的落地经历，完全可以在岗位沟通和考察重点上体现得更明确。如果面试官认为方案不够好，也可以针对关键缺陷进一步验证。招聘当然是双向选择，但至少应该让候选人感受到，自己的时间和投入被认真对待。

## 六、总结：不是怕被拒，而是不想被当成免费方案输出工具

**这次网易易盾面试最让我不爽的，不是题目难，而是问题追得很深、方案要求得很完整，最后却几乎面完就挂。**

GRPO 从概念问到奖励公式，再问训练边界情况；Deepfake 从 Backbone、数据划分问到损失设计，几乎把一个建模方案的主要环节都聊了一遍。我也不是只说做不了，而是尽可能把自己的理解和设计方案完整讲了出来。

不合适可以拒绝，技术方案不够好也可以否定。**但如果一场面试需要候选人投入大量时间讲系统设计、训练策略和完整建模方案，招聘方也应该有相应的评估诚意。**

最终我的直观感受就是：**像是被拉来认真讨论了一轮方案，刚讨论完就被淘汰了。** 是否真的存在套方案的意图，我无法判断；但就这一次面试而言，这种体验确实让我很失望，也很难让我对这套招聘流程留下好印象。
